# Verify

Run verification only after the user or an external Coding Agent reports remediation complete. The claim itself is not Evidence.

Use `rally verify --report <path> --scope full --json`, inspect the disclosed fresh-read permissions, then resume with `--resume <token> --permissions '<json>'`. If the next result requests `authenticated_journey_results`, follow [protected-journeys.md](protected-journeys.md) before resuming with `--journey-results '<json>'`. Rely on the new immutable Report, Evidence Index, Manifest Drift list, and source-to-current comparison. A completed full Verify atomically commits its canonical Record, rederived View, Evidence Index, and referenced digest-addressed structurally allowlisted Evidence under the explicit current repository's `.launchrally/` history. Validated dead-writer transactions are recovered across generated Report IDs; a live transaction stops shared-store mutation, and malformed, partial-visible, or unowned transaction state fails closed. Recovery never deletes Evidence referenced by visible Reports. Recoverable persistence errors never claim Verify completion, and existing historical Reports or Evidence are never overwritten or pruned. The current-Report cache remains best effort and non-authoritative.

For a limited recheck, use `--scope targeted --checks '["check.id"]'`. A targeted result has `assessment_scope: "targeted_only"`, carries no Report, and must never be presented as a whole-release Launch Ready assessment.
